# FunBun Skill

Используй этот скилл для команд к `~/fun/fun.ts`, когда пользователь пишет разговорным языком.

## 1) Быстрый маппинг намерений

- Показать активные: `bun ~/fun/fun.ts show a`
- Показать backlog: `bun ~/fun/fun.ts show b`
- Показать выполненные: `bun ~/fun/fun.ts show c`
- Показать удалённые: `bun ~/fun/fun.ts show d`
- Показать цели: `bun ~/fun/fun.ts show e`
- Добавить в active: `bun ~/fun/fun.ts add a "<title>"`
- Добавить в backlog: `bun ~/fun/fun.ts add b "<title>"`
- Добавить в цели: `bun ~/fun/fun.ts add e "<title>"`
- Завершить задачу: `bun ~/fun/fun.ts complete <N>`
- Удалить задачу: `bun ~/fun/fun.ts delete <N>`
- Показать статистику: `bun ~/fun/fun.ts stats`
- Разбить задачу: `bun ~/fun/fun.ts split <N>` (active)
- Разбить цель / задачу из backlog: `bun ~/fun/fun.ts split e <N>` / `split b <N>`
- Очистить выполненные из active: `bun ~/fun/fun.ts refresh`
- Инициализация: `bun ~/fun/fun.ts init`

## 2) Разбор естественной речи (включая голос)

Трактуй голос как обычный текст после распознавания. Учитывай шум:

- Пользователь может обращаться на русском и на английском; обрабатывай оба языка одинаково.
- Игнорируй слова-паразиты: "типа", "короче", "ээ", "ну".
- Исправляй очевидные опечатки/ASR-ошибки без отдельного подтверждения.
- Если пользователь сказал действие неявно, выбирай ближайшее намерение по смыслу.

Примеры:

- "добавь в активные купить молоко" -> `add a "buy milk"`
- "закинь в бэклог идею про лендинг" -> `add b "landing idea"`
- "добавь в цели спорт" -> `add e "sport"`
- "закрой третью" -> `complete 3`
- "удали задачу номер 5" -> `delete 5`
- "покажи что на сегодня" -> `show a`
- "стату" -> `stats`
- "почисти выполненные" -> `refresh`

## 3) Нормализация названий задач для add

Перед `add` нормализуй заголовок:

- Переведи в короткий английский.
- Используй lowercase.
- Держи обычно 2-4 слова.
- Сохраняй только то, что поможет потом вспомнить задачу.
- Если есть важные дата/время/место, оставь кратко.

Примеры:

- "погуглить билеты в дубай" -> `dubai flights`
- "позвонить маме" -> `call mom`
- "встреча с васей завтра в 5" -> `meet vasya 5pm`

## 4) Правила уточнений

Не задавай лишних вопросов. Уточняй только если действие нельзя выполнить однозначно.

Уточняй обязательно:

- Для `complete/delete/split` отсутствует номер строки.
- Пользователь говорит "удали" без явного объекта (непонятно, что удалять).
- Пользователь просит добавить задачу, но текст задачи пустой.

Не уточняй:

- Явные команды с номером или явным текстом задачи.
- Небольшие языковые огрехи.

## 5) Исполнение и ответ

- Выполняй команду и показывай пользователю короткий итог.
- При ошибках `fun.ts` передавай суть ошибки как есть.
- Если получено `not initialized` или `file not found ... run 'fun init'`, предложи и при подтверждении запусти `bun ~/fun/fun.ts init`.

Формат ответа после успешного действия:

- Что сделано одной строкой.
- Короткая выжимка вывода команды.

## 6) Split (декомпозиция)

Если пользователь просит декомпозировать задачу и сразу даёт подзадачи списком, запускай `split N` (или `split e N` для целей, `split b N` для backlog; номер — строка в соответствующем списке) и передавай подзадачи в stdin построчно, пустая строка в конце.

Если подзадач нет, сначала спроси их списком, затем выполни `split`.

## 7) Границы

- Не редактируй напрямую `a.md/b.md/c.md/d.md/e.md`, если можно сделать то же через `fun.ts`.
- Не выдумывай номера строк.
- Не выполняй потенциально разрушительные shell-команды вне сценариев `fun.ts`.
